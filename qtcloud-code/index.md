# 量潮编程云工作意图

新手上手的时候，不需要先理解”为什么要这么做“，而是先跟着工具走，走多了自然就懂了。工具本身就是教程。

工具本身的迭代过程，就是在沉淀这套方法论。每次有人用工具发现新的差异类型、新的重构路径，都可以反哺到工具里，形成正循环。

## 评审阶段自动化

每次提交代码时，工具自动检查：上下文是否干净、模块边界是否清晰、有没有违反架构原则的代码。不是靠人肉 review，而是靠规则引擎直接报错。

## 反思阶段可视化

依赖图分析做成一个 dashboard，左边是你画的预期架构图，右边是工具生成的实际依赖图，差异自动高亮，并且按那四类差异自动归类。人只需要点击确认或修正分类。

## 重构阶段模板化

针对每类差异，预设几种常见的重构路径。比如”AI 自行发明的结构“→ 删除或合并；”违反架构原则“→ 移动或重构。AI 根据模板生成具体改动方案，人只需要选。
